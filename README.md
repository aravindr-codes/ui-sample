# Disbursement Console (ifcui)

A local-first reference UI for **Programs → Beneficiaries → Disbursements**, built to validate the frontend stack and the **API-by-interface** pattern before any server work begins. It runs with no backend: a Mock Service Worker in the browser serves a real REST + Server-Sent-Events API from an in-memory store, and switching to the real Azure Function Apps is a `config.json` change.

- **One static build, configured at runtime.** `config.json` is fetched before React renders; the same bundle serves dev, qa, uat and prod.
- **The UI talks only to TypeScript interfaces** (`ApiClient`). Adapters: in-memory, HTTP→MSW, HTTP→real API.
- **Everything is contract-tested.** One test suite runs against every adapter, so they stay interchangeable.

`PLAN.md` holds the original design, the milestones and the open decisions.

## Quick start

Requirements: **Node ≥ 22** and **pnpm 10** (`corepack enable` picks up the pinned version).

```bash
pnpm install                                 # also installs the lefthook pre-commit hooks
pnpm dev                                     # http://localhost:5173 with the MSW mock API
```

What you get locally:

- About 3 programs, 500 beneficiaries and 2,000 disbursements from a deterministic seed.
- Realistic latency (150–400 ms).
- A **simulator** that plays other operators (approving, verifying, registering) every 6–14 s, so the live-activity bell fills up.

The mock data lives in the page. Reload the page to reset it.

> **Tip:** don't test exports or uploads inside an automated (Playwright) browser window. Playwright captures file dialogs and downloads there. Use your normal browser.

## Commands

All commands run from the repo root.

| Command | What it does |
|---|---|
| `pnpm dev` | Vite dev server on :5173 (`apiMode: msw`) |
| `pnpm build` | Type-checks all packages, then `vite build` → `apps/web/dist` |
| `pnpm preview` | Serves `dist` on :4173 (MSW still on via `config.json`) |
| `pnpm test` | Vitest: contract package + web unit and contract tests |
| `pnpm e2e` | Playwright against a fresh `build` + `preview` |
| `pnpm check` | Biome lint/format check + `tsc` for every package |
| `pnpm format` | Biome auto-fix (format, organize imports, safe lint fixes) |

Running a subset:

```bash
pnpm --filter web exec vitest run tests/contract.test.ts -t "documents"   # one describe/it by name
pnpm --filter @ifcui/api-contract exec vitest run tests/sse.test.ts       # one file in the contract package
pnpm --filter web exec playwright test -g "invalid runtime config"        # one E2E test by title
pnpm --filter web exec playwright install chromium                        # first E2E run on a machine
```

**Definition of done** for any change:

```bash
pnpm check && pnpm test && pnpm build && pnpm e2e
```

The pre-commit hook (lefthook) runs Biome on staged files and type-checks the workspace, and it blocks the commit on failure.

## Stack

| Concern | Choice |
|---|---|
| Build / dev server | **Vite 8** (Rolldown) + `@vitejs/plugin-react` |
| Language | **TypeScript 7** (native `tsc`), `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` |
| Routing | **TanStack Router** (file-based, type-safe params and search) |
| Server state | **TanStack Query** (loaders prefetch; components use `useSuspenseQuery`) |
| UI | **MUI 9** only (no Tailwind), **MUI X DataGrid** free tier, Open Sans (self-hosted) |
| Validation | **Zod 4**, the single source of types and runtime checks |
| Forms | React Hook Form + Zod resolver, reusing contract schemas |
| Mock API | **MSW 3** (service worker in the browser, `msw/node` in tests) |
| Export | CSV (built in) and PDF (jsPDF + autotable, lazy-loaded) |
| Tests | Vitest, Testing Library, Playwright, axe-core |
| Lint / format | **Biome** (replaces ESLint and Prettier) |

TanStack **Start** is intentionally not used: there is no SSR and no Node runtime in production.

## Architecture

```
React routes/components
   │  useSuspenseQuery / useMutation (TanStack Query)
   ▼
useApi() ──► ApiClient interface (packages/api-contract)
               ├─ InMemoryApiClient ──────────────► Store  (apiMode: memory)
               └─ HttpApiClient ── fetch/XHR/SSE ─► MSW handlers ─► Store  (apiMode: msw)
                                                 └► Azure Function Apps   (apiMode: http, future)
```

### The contract (`packages/api-contract`)

- **Schemas are the source of truth.** Types come from `z.infer`, and IDs are branded (`ProgramId`, `BeneficiaryId`, …).
- **Every method resolves to schema-valid data or throws `ApiError`**, with codes `not_found`, `validation`, `conflict`, `unavailable` or `unknown`. Validation errors carry per-field `details.issues[]`.
- **`routes.ts`** is the single route table. `buildPath()` is used by the HTTP client, and the `:param` patterns are used by MSW. Paths cannot drift.
- **No React or browser dependencies.** When the Function Apps arrive, bundle each one to a single file with **tsdown** (see PLAN §12).

### REST and event API

| Method | Path | Notes |
|---|---|---|
| GET | `/programs` · `/programs/:id` · `/programs/:id/stats` | stats = counts per status + approved amount |
| GET | `/programs/:id/beneficiaries?page&pageSize&sort&q&status` | server-side paging, sort (`field:asc\|desc`), search |
| POST | `/beneficiaries` | create (starts `pending`; closed programs → 409) |
| GET | `/beneficiaries/:id` | |
| POST | `/beneficiaries/:id/status` | transitions enforced (`pending→verified\|suspended`, …) |
| GET/POST | `/disbursements` | list with `programId`, `beneficiaryId`, `status` filters / create (beneficiary must be verified) |
| GET | `/disbursements/:id` | |
| POST | `/disbursements/:id/approve` | 409 if already approved or beneficiary not verified |
| GET/POST | `/beneficiaries/:id/documents` | list / multipart upload (`file`, `kind`); PDF, PNG, JPEG, TXT, CSV ≤ 10 MB |
| GET | `/documents/:id/content` | download with RFC 6266 `Content-Disposition` (Unicode-safe) |
| DELETE | `/documents/:id` | |
| GET | `/events` | `text/event-stream` of `DomainEvent`s; honors `Last-Event-ID` |

Dev-only endpoints (MSW only, not part of the contract):

| Method | Path | Body |
|---|---|---|
| POST | `/api/__dev/reset` | (none): restores the seed |
| POST | `/api/__dev/chaos` | `{ "failureRate": 0..1, "latencyMs": [min, max] }` |
| POST | `/api/__dev/simulation` | `{ "enabled": bool, "intervalMs": [min, max], "tick": true }` |

### Live events (SSE)

- **Producer:** every store mutation emits a `DomainEvent`. Each event carries the full updated entity and an `actor`, and events are kept in a 500-event replay buffer.
- **HTTP client:** uses **fetch-based SSE**, not `EventSource`, so it can send `Authorization` headers later. It reconnects with exponential backoff and jitter, honors the server's `retry:`, resumes with `Last-Event-ID`, and drops events that fail the contract.
- **UI:** `LiveEventsProvider` (in `components/LiveEvents.tsx`) subscribes once. For each event it writes the entity into the Query cache and invalidates affected lists and stats, so open screens update in place. The top bar shows the connection state and a bell that opens the activity feed.

### Runtime configuration

`apps/web/public/config.json` is validated by `RuntimeConfig` (`src/config/runtimeConfig.ts`). An invalid file renders a startup error that lists every problem. `import.meta.env` is used only for build metadata, never for environment settings.

```json
{
  "apiMode": "msw",
  "apiBaseUrl": "/api",
  "mock": {
    "latencyMs": [150, 400],
    "failureRate": 0,
    "seed": 20260930,
    "simulation": { "enabled": true, "intervalMs": [6000, 14000] }
  },
  "features": { "disbursementApproval": true }
}
```

| `apiMode` | Adapter | Network | Use |
|---|---|---|---|
| `msw` | HttpApiClient → service worker | real `fetch`/XHR/SSE, intercepted | local dev, E2E |
| `memory` | InMemoryApiClient | none | fastest local runs, isolation |
| `http` | HttpApiClient → `apiBaseUrl` | real | Function Apps |

Mock code (faker seed, store, MSW) loads only in `msw`/`memory` mode. An `http` deployment never downloads it.

## UI conventions

- **Styling is MUI only.** Layout uses `Box`/`Stack`/`Grid`/`Container`, and styling uses `sx`/`styled()` with theme tokens. Raw colors exist only in `src/theme/theme.ts`, which mirrors the worldbank.org palette: the blue scale, navy `#012740`, neutral `#f5f7f9`, and an orange focus ring. Light and dark mode come from `colorSchemes` with CSS variables.
- **Grids use `DataTable`** (`components/DataTable.tsx`) and are never wired by hand. It provides server paging and sorting bound to URL search params, a debounced search box, a filter slot, fixed-height virtualized scrolling, and an Export menu (PDF / CSV). Export fetches **all rows matching the current filters and sort**, not just the visible page, capped at 10,000. Each column declares its export form with `export: { csv, pdf }`, or `export: false`.
- **URL is the state.** Grid page, size, sort, search and filters are in the URL, validated by Zod schemas in `queries/search.ts`. Malformed values fall back to defaults.
- **Data loading:** route `loader` → `queryClient.ensureQueryData(xQueries.y(api, …))`. Components call `useSuspenseQuery` with the **same** factory.
- **Mutations** invalidate by key prefix (`queryKeys` in `queries/index.ts`). Beneficiary status change is optimistic with rollback. When starting several mutations in parallel, use `mutateAsync` per item, because per-call `mutate(…, { onSuccess })` callbacks only fire for the latest call.
- **Errors** become user text in one place (`api/errors.ts` → `describeError`). Only `unavailable` errors are retried.
- **Accessibility:** routes have landmarks, a skip link, labelled grids and controls, and correct list semantics. Axe (WCAG 2.1 AA) runs in E2E.

## Testing strategy

| Layer | Where | What |
|---|---|---|
| Contract | `apps/web/tests/contract.test.ts` | One suite × two adapters (memory, HTTP+MSW in Node): paging, sort, filters, validation, transitions, documents (binary + Unicode names), SSE events. Plus HTTP-only checks: contract-violating responses, Last-Event-ID replay, reconnect, auth header |
| Unit | `packages/api-contract/tests`, `apps/web/tests` | Route builders, schemas, SSE parser, Content-Disposition, file validation, URL search schemas, simulator |
| E2E | `apps/web/e2e/app.spec.ts` | Golden paths, CSV/PDF export contents, document upload/download/delete, live events, failure injection + retry, optimistic rollback, invalid config, feature flag, dark mode, memory mode, axe |

E2E tests serve their own `config.json` through `page.route` (low latency, simulation off), exactly as a deployment would. The bundle under test is identical to production.

## Adding a feature: checklist

1. Add or extend the Zod schema and interface in `packages/api-contract`, and the path in `routes.ts`.
2. Implement it in the store, the MSW handlers and **both** adapters.
3. Add cases to the shared contract suite. They run against every adapter automatically.
4. Add `queryOptions`/mutations in `src/queries`, then the route and components. Grids go through `DataTable`.
5. If the change affects live data, emit a `DomainEvent` from the store and handle it in `applyEventToCache`.
6. Add or extend an E2E test and run the definition of done.

## Deployment (next step, see PLAN §12)

Build once (`pnpm build` → `apps/web/dist`), publish `dist` as an artifact, and replace `config.json` per environment (`apiMode: "http"`, `apiBaseUrl` pointing at the Function Apps). Auth plugs into `createHttpApiClient({ getToken })` (MSAL / Entra ID).
